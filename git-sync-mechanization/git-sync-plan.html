Git 同步機制化 v2

從「靠我記得讀文件」變成「session start 就自動查」——同步查核走 script，repo 清單維護走 skill。

2026-07-26 C機 · TW-KARENSHEN 待 Karen 核准
01

事故現場：三層疊在一起的漏洞

C機開工這次漏掉 dotclaude 落後 10 commits、qoome 底下 6 個 nested repo 落後 remote。往下追，問題不是單一原因，是三層疊加。

01

我自己沒讀文件就動手

看到「開工」沒去讀 start-work-flow.md，直接土法動手，範圍縮到目前 cwd（qoome-content-factory）。

02

唯一機制上保證會跑的東西，本來就不查 remote

daily-flow-inject.sh（比對「開工/早安/briefing」字串觸發）只呼叫 today-touched.sh / wip-detector.sh——兩支都只查本機 dirty / unpushed，從不 git fetch。

03

repo 探索範圍本身有洞

check-sync.sh 用 for dir in "$VIBE_DIR"/*/（只看第一層）；today-touched.sh/wip-detector.sh 用 find -maxdepth 2。兩者都看不到 qoome/ 底下再巢狀一層的 9 個獨立 repo——因為 qoome/ 自己也是一個 repo，形成「container repo 裡面包 repo」的結構。

意外發現的死碼

~/dotclaude/scripts/auto-pull.sh 其實早就掛在 SessionStart hook 上（settings.json matcher startup），但它判斷「vibe 是不是 git repo」那段（if [ -d "$VIBE/.git" ]）自 2026-07-21 vibe 拆成純資料夾之後就恆為假——這支既有的「開工自動同步」邏輯，已經靜默失效超過一個月。

03

職責兩分：Script 管執行，Skill 管清單

Script
  • check-sync.sh --repos-file 讀固定清單，不做探索判斷
  • 沿用既有 process_repo()：remote / fetch+behind / unpushed / dirty / gitignore / zombie 全套
  • 每個 repo 背景平行跑，各自寫暫存 JSON，wait 後 jq -s 合併
  • 單一 repo fetch 失敗（帳號沒切對）只記一行，不中斷整批
  • 登記路徑若已不存在 → 標記「registry 有髒路徑」，但不擅自修改清單
  • Part D 新增：audit-registry.sh --summary-json 純本機 find（不連網），每次都跑，drift 計數 > 0 就在 additionalContext 補一行提醒
Skill
  • audit-registry.sh（無 flag 版）遞迴 discover 真實存在的 repo，跟清單做完整 diff
  • 發現「有 repo 沒登記」——可能是新專案，也可能是不小心巢狀出來的 .git，兩種情況都需要人判斷
  • 發現「登記了但路徑消失」——列為候選移除，問過才刪
  • 掛勾 new-project-flow.md：建新專案時自動 append，不用等手動盤點
  • 明確不排週期性自動跑——被叫到才跑、或看到 Part D 提醒才跑
為什麼銜接 new-project-flow 之後還要留 Part D

new-project-flow 銜接只擋得住「照流程建專案」這條路徑；擋不住手動 git init、忘記走流程、複製別人專案這類意外。Part D 的 discovery 是純本機檔案系統操作，成本接近零，所以讓它每次 session start 都跑，當作銜接失靈時的保底——即使某次真的漏登記，下次開 session 也會被動提醒，不會無限期 silent drift。

05

驗證方式

1

種子清單：對空 registry 跑一次 audit-registry.sh，確認能列出目前所有實際 repo（含 qoome 巢狀 9 個），拿這份輸出當初始 repo-registry.txt。

2

效能：check-sync.sh --json --repos-file repo-registry.txt 實測秒數，跟內層 12s timeout 比對，確認平行化真的有效。

3

行為：手動跑 auto-pull.sh，確認 additionalContext 裡有 registry 掃描摘要；找一個故意落後的 repo 驗證抓得到 behind。

4

Drift 偵測：臨時在 vibe 下建一個假 repo，跑 audit-registry.sh 確認「有 repo 沒登記」分支正確觸發，測完清乾淨。

5

timeout 排序：確認 settings.json 外層 timeout（15）永遠大於 script 內層 timeout（12）。

6

文件：檢查 new-project-flow.md 新增那行是否清楚、跟既有登記步驟銜接合理。

06

已知限制

Gh 多帳號脆弱性

iven-qoome org 系列 repo 走 HTTPS + gh credential helper，帳號沒切對就 403/404。背景 fetch 撞到只記錄失敗，不會自動切帳號。長期建議改 SSH multi-account alias，但不塞進本次範圍。

每次 session 都有延遲

不管這次要不要碰 git，每個 session 開場都會多花幾秒做同步檢查——這是 Karen 明確要的行為（「每次 session start 就自動觸發」），是已知取捨，不是 bug。
