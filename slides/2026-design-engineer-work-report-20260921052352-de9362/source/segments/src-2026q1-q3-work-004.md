# 二、Bridge Visual Designers ↔ MKT

## 二、Bridge Visual Designers ↔ MKT ### 1. MKT Template Refinement 與設計語言收斂 **Duration：** 2026/06–2026/07 **題目：** 以 benchmark、匿名偏好測試與設計師判讀，協助 MKT 建立可共識化的視覺內容方向。 **大綱：** - 以品牌 moodboard 建立 2×2 風格分佈，檢視內部區域帳號在情緒與媒材上的分歧。 - 建立三語 swipe survey，將品牌素材去識別後收集結構化偏好與理由。 - 將量化與質化回饋整合為分析頁，保留每一項視覺手法的設計師意見，最後收斂為 warm minimalism design language 與 IG mockup 提案。 - 將整套研究、蒐集、評估、設計語言收斂的流程，形成可重複使用的 evaluation-driven pipeline。 **可量化資料：** 處理 **85 張**去識別化圖像、建立 **14 張**三語 survey 卡，收到 **8+1 份**回覆並完成量化與質化整合。 ### 2. 社群內容生成 Orchestrator 與範本供給鏈 **Duration：** 2026/08–至今 **題目：** 將社群內容生成從一次性 prompt，轉為 MKT 可操作、可選版型、可同步上游資源的流程。 **大綱：** - 建置 `social-media-gen` orchestrator，包含 preflight、editorial alignment、素材補圖、mockup preview、checkpoint 與交付規範。 - 維護 Cover、UI mockup、Blurring / Color Temperature 三個視覺表現家族，並將上游資源以 manifest 與 SHA 檢查同步。 - 根據同仁 dogfood 回饋補足 template guide、版型欄位、disabled gate 與跨 Runtime 說明；不另維護 Claude / Codex fork。 **可量化資料：** 8 月記錄 **24 commits**；完成 **9 個 UI mockup 版型**的精確截圖與使用指引，並經 4–5 輪內部 dogfood 迭代。 ### 3. MKT 視覺素材匯出與交付工具 **Duration：** 2026/08–2026/09 **題目：** 將設計資產與交付範本變成 MKT 可直接取得、可追蹤的素材供給。 **大綱：** - 建立設計交付 template 的 12 頁 demo，作為 AI 產出與既有 PowerPoint 品質的對照基準。 - 於 9/3 完成 `figma-export.sh`：依 Figma SECTION / FRAME 樹遞迴匯出 PNG @2x，並以 manifest 記錄輸出狀態、來源與檔案清單。 - 將輸出流程、品牌治理檢查與操作文件一併交付，讓共享素材庫可被重複更新而非手動整理。 **可量化資料：** Figma export 工具為 **471 行**互動式 shell script；以 **4 個真實 Figma URL**驗證，共正確輸出 **75 個檔案**。 ### 4. AI 內容品質評估與語音方法論 **Duration：** 2026/06–2026/07 **題目：** 將 AI 內容生成由「能否寫出來」轉為可評估、可比較、可修正的視覺與語音品質流程。 **大綱：** - 分析公司 IG 內容表現，建立以控制變因為前提的視覺 / 內容判讀，而非僅依單一觸及或互動數字下結論。 - 製作三語 blind evaluation 頁與 stakeholder 回饋機制，作為內容與風格版本的比較基礎。 - 完成 Case-Tom persona 專案的多輪 Turing test，將失敗樣本整理為可執行的 rule patch 與重寫技能。 - 將方法論整理成內部分享，並以簡報本身的多輪評測驗證產出品質。 **可量化資料：** 分析約 **223 篇**IG 貼文並產出 **8 張**互動圖表；Case-Tom 完成 **20 輪 Turing test、61.5% 命中率**，產出 **21 頁**內部分享簡報。 ---
