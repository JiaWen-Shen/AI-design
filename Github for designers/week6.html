.claude vs dotclaude：為什麼分兩家

Runtime vs source — connected via symlink

~/.claude/ = Claude Code runtime working dir（每次對話都會自己寫東西進去）； ~/dotclaude/ = 你的 git source repo（只放你想跨裝置同步的靜態設定）。 兩家透過 symlinkSymlink = 軟連結，作業系統的「捷徑指標」。~/.claude/CLAUDE.md 表面看是個檔案，實際內容存在 ~/dotclaude/CLAUDE.md。一檔兩路徑、改一邊兩邊同步。Symlink = soft link, an OS-level shortcut pointer. ~/.claude/CLAUDE.md looks like a file but its content lives in ~/dotclaude/CLAUDE.md. One file, two paths — edit either, both sync. 連起來。~/.claude/ = Claude Code runtime working dir (Claude Code writes to it on every chat); ~/dotclaude/ = your git source repo (only static configs you want synced across devices). Connected via a symlink.

PART 1 · DOTCLAUDE

如何維護：定期檢視 & 簡化

Routine review & trim

設定檔會隨時間長大，每加一條規則都覺得「有用」，但檔案膨脹會吃 context、變得難讀、容易被截斷。建議每 1-2 週做一次檢視。Config grows over time. Bloat eats context, hurts readability, risks truncation. Review every 1-2 weeks.

① 請 agent 摘要① Ask agent to summarize
  • 「摘要我的 CLAUDE.md，每段一句話」"Summarize my CLAUDE.md, one line per section"
  • 看摘要能不能複述出你心中的規則Check whether the summary matches your intent
  • 講不清楚 = 寫得不夠精簡Unclear summary = unclear writing
② 檢查重複/過時② Check duplicates / stale
  • 同一規則寫兩次 → 合併Duplicate rules → merge
  • 過去某次踩雷的個別解法 → 評估還適用嗎One-off lesson → still relevant?
  • 沒在用的 skill / hook → 移除Unused skill/hook → remove
③ 簡化：抽出來當 ref③ Simplify: extract as ref
  • 某段落變長 → 抽成獨立檔Long section → separate file
  • 用 @CODE_BEHAVIOR.md 在 CLAUDE.md 引用Reference via @-import
  • 主檔回歸精簡、需要才展開Main file stays lean, expands on demand
實例：我 6/27 把 CLAUDE.md 從 261 行 → 190 行（-27%），把「Coding Conventions」+「Code Behavior」兩段抽成 CODE_BEHAVIOR.md，主檔用 @CODE_BEHAVIOR.md 引用——AI 行為不變，主檔清爽很多。Real example: CLAUDE.md 261 → 190 lines (-27%) on 6/27 — extracted Coding Conventions + Code Behavior to CODE_BEHAVIOR.md, referenced via @CODE_BEHAVIOR.md in the main file. Same AI behavior, much cleaner main file.

什麼「不能放」進 dotclaude repo

What must stay out of git
不放的東西What stays out為什麼Why放哪Put where
.env / token / API key外洩 = 帳號被盜、$$ 燒掉Leak = account hijacked, $$ burned放 ~/Jottacloud/.env.*（雲端、不進 git）In ~/Jottacloud/.env.* (cloud, not git)
session transcript（projects/*/sessions）每天幾百 MB、含對話內容Hundreds of MB/day, contains chats本機自動產生、別 commitAuto-generated locally; don't commit
node_modules / __pycache__ / .DS_Store每台 OS 不同、bloat repoOS-specific, bloats repo直接 ignoreJust ignore
個資（email 內容、客戶資料）PII (email content, client data)repo 可能變 publicRepo may become public留本機或加密儲存Keep local or encrypt
.gitignore 必含三條.gitignore must have 3
.env* # 所有 env 檔 projects/*/sessions/ # transcript **/node_modules/ # 依賴目錄.env* # all env files projects/*/sessions/ # transcripts **/node_modules/ # dependency dirs
沒設 gitignore 就 push：token 被 GitHub 掃到 → 帳號鎖、key 自動 revoke、要重申請。先設好再 commit。Push without gitignore: GitHub secret-scan catches the token → account locked, key auto-revoked, reapply. Set gitignore before commit.
