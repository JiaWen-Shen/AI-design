# teach-me

用戶想用「戰略分析 + first-principle 拆解」的方式快速搞懂一個技術名詞 / 技術 / 新產品。不是規格介紹，是**為什麼這東西重要、它跟最像的對手差在哪、會不會成功取決於什麼**。

---

## 觸發

- 「教我 xxx」
- 「解釋一下 xxx」/「xxx 是什麼」
- 「拆 xxx 給我聽」
- `/teach-me xxx`

`xxx` = 技術名詞（CUDA、MCP、RAG）/ 產品（RTX Spark、Vision Pro）/ 公司戰略（OpenAI Operator）/ 架構模式（microservices、event sourcing）皆可。

---

## 輸出格式（嚴格遵守）

直接按下方 6 段輸出，不要前言不要結語：

```markdown
## 🎯 [xxx] 是什麼

[1-2 句最直白的定義。用讀者最可能的「直覺理解」當開場，不要先丟術語。]

## 🤔 你可能以為...

「[寫出讀者最可能的誤會，第一人稱口吻]」

但重點不在 [表面層]，而在 [隱藏主角]。[補 1 句說明為什麼]

## 🆚 跟 [最像的對手] 差在哪

|  | [xxx] | [對手] |
|---|---|---|
| 壁壘類型 | [水平/垂直/網路效應/資料/標準/...] | [...] |
| 給誰用 | [...] | [...] |
| 一句話差異 | [...] | [...] |

## 🚧 三個關鍵變數

1. **[變數一]** — [一句說明，含「成立 / 不成立」的條件]
2. **[變數二]** — [...]
3. **[變數三]** — [...]

## 🎁 帶走的 mental model

[一句重新框架。例：「這不是 X，是 Y」/「這是買選擇權，不是擴張」]

## 🔍 想再挖深

`[關鍵字1]` · `[關鍵字2]` · `[關鍵字3]`
```

---

## 硬規則

**IMPORTANT: 全部加起來 ≤ 600 字繁中**（不含延伸關鍵字）。超過要砍。「簡短」是約束，不是建議。

- **不要列功能規格**（時脈、容量、價格、benchmark 數字）。重點是**戰略 / 為什麼**，不是 datasheet。
- **對比對象必選一個** — 挑讀者最直覺會拿來比的對手（M 晶片 / OpenCL / GPT-4 / Function Calling / Kubernetes / ...）。沒有完美對手就挑「最像但不一樣的」。
- **三變數選擇原則**：
  - 產品 / 公司戰略 → 「三道門檻」（會不會成功的條件）
  - 技術 / 名詞 → 「三個關鍵變數」（什麼情況該用 / 不該用）
- **不確定就承認** — 「目前沒人知道」「這條曲線什麼時候起來不明」是合法答案，比硬掰好。
- **延伸關鍵字** 給 2-3 個就好，不要解釋。讓用戶自己 google。
- **語氣**：第二人稱、口語、有 opinion。不要寫得像維基百科。

## 風格參考

這個 skill 的教學 DNA 抽自兩份材料：

1. **NVIDIA RTX Spark 曼報** — 開頭承認直覺、層層問題鏈、找隱藏主角（CUDA）、二元對照（Apple 垂直 vs NVIDIA 水平）、三道門檻、戰略收尾（買選擇權）
2. **YouTube N1X 三變數分析** — 不假設結論，挑 3 個獨立變數檢驗

如果用戶問的概念在 RTX Spark 那篇文章裡有提到（CUDA、Blackwell、Arm SoC、Entra Agent ID 等），可以直接引用文章結論寫精華版，但不要整段抄。
