PART 1 · CLAUDE.MD

兩個都讀，誰說了算？

Both are read — who wins?
  • Claude Code 兩個都載入：全域先、專案後（越近工作目錄越後讀）Claude Code loads both: global first, project after (closer to the working dir = read later).
  • 衝突時 → 專案層更具體，覆寫全域On conflict → the project level is more specific and overrides global.
⚠ 衝突實例 · conflict example
全域說：用個人帳號 ／ 專案說：用工作帳號 → 在這個專案，聽專案的。 Global says: use personal account / Project says: use work account → in this project, the project wins.
心智模型：全域 = 預設值，專案 = 在地覆寫（override）Mental model: global = default, project = local override.

PART 1 · 維護

維護原則 — 保持精簡

Keep them lean
行數上限 / 載入成本
  • MEMORY.md：索引開機只載「前 200 行 / 25KB」索引保持精簡，細節拆主題檔MEMORY.md index loads only the first 200 lines / 25KB at startup — keep it lean, split detail into topic files
  • CLAUDE.md：整份進 context、每回合都在肥 = 一直燒 token（全域先、專案後覆寫）CLAUDE.md sits fully in context every turn — bloat = burning tokens constantly
維護原則
  • 只寫「專案特例」Claude 原生就會的（寫乾淨 code、改前先解釋、不亂加註解）不用寫only write project-specific exceptions — skip what Claude already does by default
  • 只記「現在有效」的過時就刪——錯的記憶比沒記憶更糟keep only what's currently true — wrong memory is worse than none
  • 不堆歷史歷史留 commit / 日誌，別塞進規範檔leave history in commits / logs, not in the rules file
要省 token 只能砍內容：@import 不省（照樣全載，只是分檔）；少用的細節改成「在 CLAUDE.md 提路徑、讓 agent 需要時再 Read」或放進 skill；定期 /memory 檢視 + prune。To save tokens you must cut content: @import doesn't help (still fully loaded, just split); move rarely-needed detail to a path the agent reads on demand, or into a skill; prune regularly with /memory.

PART 1 · 強制力與限制

規則有多硬？

How strong is it, really?
做得到 · 強制力
  • 每次 session 自動載入，agent 會「盡量」遵守auto-loaded every session; the agent tries hard to follow
  • 比口頭叮嚀可靠——規則固定在 context 裡more reliable than verbal reminders — rules are pinned in context
  • 多數情況有效works most of the time
做不到 · 限制
  • 不是鐵律：長對話 / context 壓力下仍可能漏看或違反not ironclad — long chats / context pressure can still miss or break rules
  • 規則越多越雜 → 注意力被稀釋more/messier rules → diluted attention
  • memory 可能記錯 / 過時memory can be wrong or stale
CLAUDE.md / memory = 強力提示；要「機械式」擋住危險操作（誤 push main、rm -rf）得靠 hooks。CLAUDE.md / memory are strong nudges; to mechanically block dangerous actions (wrong push to main, rm -rf) you need hooks.

工具補不了「源頭沒更新」

A tool can't fix specs nobody updates
  • 根因常是 PM/RD 沒把口頭 / 會議結論回寫文件——這是溝通問題。The root cause is usually PM/RD not writing verbal / meeting decisions back into docs — a communication problem.
  • design-context 是「持續同步 + 提醒」，不是「保證正確」。design-context is "continuous sync + flagging", not "guaranteed correctness".
風險若硬抓「過時的 requirement」，反而跟現行設計打架、製造 conflict。Risk: forcing a stale requirement fights the current design and manufactures conflict.
