PART 2 · 換裝置 SOP

換裝置流程（個人 settings 為例）

Switching machines — personal settings example
Terminal — 第一次 first time
# 1. clone 設定 repo 到 home git clone https://github.com/you/dotclaude.git ~/dotclaude # 2. symlink ~/.claude/ → ~/dotclaude/ bash ~/dotclaude/scripts/bootstrap-symlinks.sh # 之後每次換機只要 git clone + 跑 bootstrap
Terminal — 之後 daily
# A 機改完 cd ~/dotclaude git add -A && git commit -m "..." git push # B 機開工前 cd ~/dotclaude git pull

這套模式同時解決「設定一致」+「可以 review 改了什麼」+「壞掉可以 git revert」。 This pattern gives consistency + reviewable diffs + revertable mistakes.

PART 2 · 為什麼

為什麼 .git/ 不能放雲端同步資料夾？

Why .git/ doesn't belong in cloud sync

雲端同步工具的工作模式 = 「看到檔案變了就上傳」。但 .git/ 裡的 refs 和 objects 變化頻率極高，又會多台機器同時動 → 競態 race condition：Cloud sync = "file changed → upload". .git/ refs and objects change constantly, and multiple machines may write at once.

  • A 機 commit 完，雲端還在上傳 → B 機 pull 拿到半成品Machine A commits while cloud is still uploading → Machine B pulls a half-baked state
  • 兩台同時 commit → refs 衝突，git 認為 repo 壞了Both machines commit at once → refs conflict, git thinks the repo is broken
  • 雲端「自動修復」不一致檔案 → 整批 commit 消失Cloud "auto-resolves" mismatches → entire commits vanish
底線 Bottom line：repo 走 git remote；雲端同步只放「沒 .git/ 的純檔案」。Repos go via git remote. Cloud sync only carries plain files without .git/.

PART 3 · 錯誤恢復

Push 錯 repo / 錯帳號

Pushed to the wrong repo / account
程度怎麼救對 Claude Code 說
還沒被別人 pull（private repo）revert + force-push「我 push 錯 repo 了，幫我從遠端撤回那個 commit」
已經被別人 pull / 公司 repo不要 force-push，
開新 commit 修回去		「保留歷史，加一個 revert commit 蓋掉錯的改動」
含敏感資訊（API key、密碼）立刻 revoke key
再清歷史		「這個 commit 有 leak key，先告訴我怎麼 revoke，再清 git 歷史」
原則：private repo 出事可以暴力修；public / 團隊 repo 永遠選保留歷史的修法。Rule: private repos allow aggressive fixes; public / team repos always preserve history.

跨裝置 Conflict

Cross-device conflict
情境 scenario
# A 機 push 了 CLAUDE.md 改動 # B 機沒 pull 就改 → push → reject ! [rejected] main -> main (fetch first) error: failed to push some refs
  • B 機 git pull → 出現 merge conflictMachine B runs git pull → merge conflict appears
  • 手動選保留哪一段 → commit → pushPick which side to keep → commit → push
  • 對 Claude Code 說：「幫我解這個 conflict，A 機改了規範 X，我這邊加了規範 Y，兩個都要留」Tell Claude Code: "resolve this conflict — A added rule X, I added rule Y, keep both"
預防 > 修復：每台機器養成「開工先 pull、收工先 push」的習慣，conflict 機率會降到接近零。Prevention beats fixing: "pull before you start, push before you stop" — conflicts approach zero.
